# Data Sources

Every website, repo, and API `tracker`'s pipeline pulls from, with links. This is a hand-maintained reference — it isn't rebuilt by the hourly pipeline, so update it by hand (see [CONTRIBUTING.md](CONTRIBUTING.md)) whenever a fetcher is added or removed. For what the pipeline *outputs*, see [data/README.md](data/README.md); for career-prep resources aimed at job seekers (not pipeline inputs), see [data/resources.md](data/resources.md).

## Considered, not added

- **workopia/UK-Graduate-Jobs** and its sibling country repos (France, Germany, Spain, Netherlands, etc.) — a large, actively-updated family of graduate-job trackers. Skipped because their apply links point at Workopia's own site (an intermediary/lead-gen page), not the employer's original posting, which breaks this repo's "every row links straight to the real application page" rule — and the table is HTML, not a plain pipe-table, so it wouldn't reuse the existing generic parser.
- **jobright-ai/2026-Software-Engineer-New-Grad** — actively maintained, but every apply link routes through `jobright.ai/jobs/info/<id>?utm_campaign=…` (its own tracking redirect), not the employer's page — same rule as workopia. Also caps its list to "the last 7 days" and pushes users to a paid Airtable link for the rest.
- **Non-standard ATSes surfaced by the MENA push** — the region's employers cluster on ATSes the pipeline didn't originally read. Each has a public keyless JSON API and follows the same pattern as the existing fetchers; `scripts/verify_extra_boards.py` already has a checker for each (`platform:token`), so verify the endpoint shape (`--dump platform:token`) before building:
  - **PinpointHQ** — `{company}.pinpointhq.com/postings.json` (or a custom domain like `careers.moneyfellows.com`). **Built 2026-09-06** (`fetch_pinpoint_jobs` in `public_sources.py`) — now a supported public-layer source, see the table above. First tenants: **Tabby** (`tabby.pinpointhq.com`, 44 postings incl. "Senior Fullstack Engineer"), **Money Fellows** (`careers.moneyfellows.com`, 8, Cairo).
  - **Workable** — `apply.workable.com/api/v3/accounts/{sub}/jobs`. The Egyptian startup scene (Elmenus, Breadfast, Rabbit, …) is mostly here. Seen: **Dsquares** (`apply.workable.com/dsquares-loyalty-dmcc`, Cairo loyalty-tech, real open roles incl. DevOps Engineer). Not built yet (Lane M3).
  - **BambooHR** — `{company}.bamboohr.com/careers/list` (`{"result": […]}`). Seen: **Instabug / "Luciq"** (`instabug.bamboohr.com`, ✓ but only 1 non-software opening at check time). Not built yet (Lane M3).
  - **Recruitee** — `{company}.recruitee.com/api/offers/` (`{"offers": […]}`). Seen: **MoneyHash** (`moneyhash.recruitee.com`, valid board, 0 open when checked). Not built yet (Lane M3).
  Added so far via routes we *do* support: **Tabby** & **Money Fellows** (`pinpoint:`), **Mercor** (`ashby:mercor`, 96 jobs — San Francisco, **not** MENA), **Bosta** (`lever:Bosta`, Cairo).
- **LinkedIn company job pages** (`linkedin.com/company/<x>/jobs`) — enumerating a company's jobs from LinkedIn means scraping against its bot protection at volume, which this repo's "respect source terms" rule forbids (LinkedIn is used *only* via its unauthenticated guest job-posting endpoint, read-only, one id at a time, for the closed-link check in `scripts/net.py`). It's also unnecessary: a company's LinkedIn listings are cross-posts of its own ATS board — so fetching the Greenhouse/Lever/Ashby/Workday board (or an `aggregate_links.yml` row for a bespoke careers site) gets the same roles from a keyless, allowed source. The tell for which ATS: the "Powered by …" line in the company careers page footer.
- **General consumer job boards — Wuzzuf, Bayt, LinkedIn Jobs, Indeed, Glassdoor, StepStone, GulfTalent, Naukrigulf** — evaluated 2026-09-07 after a request to widen MENA/EMEA coverage through these. Rejected for the same reason as the LinkedIn company-pages entry below, confirmed per-site instead of assumed:
  - **Wuzzuf** — `robots.txt` explicitly disallows the exact URL shapes needed (`Disallow: /*filters`, `/*?a=`, `/*?o=`, `/*?l=`, `/*?t=` — covering both its filtered search pages and individual job-posting links) and explicitly names `ClaudeBot` in its disallow list. No JSON API backs the search pages either — the HTML is server-rendered with no `__NEXT_DATA__`/API reference to key off.
  - **Bayt** — `robots.txt` disallows `*filters[` and all of `/en/jobs/*-jobs/` (its search-results path) for every crawler, and carries a blanket `Disallow: /` naming `LinkedInBot` and `IndeedBot` specifically. Its advertised "REST JSON Jobs" feed is a paid partner integration, not a keyless API.
  - **LinkedIn** — even a single bare request for `robots.txt` returned a Google reCAPTCHA challenge page. No path to polling this without solving CAPTCHAs at scale.
  - **Indeed** — the public "Job Search API" was discontinued; what remains requires Publisher/Partner Program approval, not a keyless call.
  - **Glassdoor** — no public API of any kind; even `robots.txt` is served from behind Cloudflare with a redirect, consistent with heavy bot-protection on the actual job pages.
  - **StepStone** — its job-feed API is a paid XML jobfeed arrangement, not free/keyless.
  - **GulfTalent, Naukrigulf** — same category (major commercial job portals monetizing search traffic); no public JSON API found, and the ToS pattern above (disallowing other job boards' bots, gating real feeds behind partner deals) is standard for this class of site.
  All of these are consumer job-search engines that monetize aggregated listings, structurally unlike Greenhouse/Lever/Ashby/Workday (ATS platforms whose employer customers *want* their own postings polled). Scraping them would mean fragile HTML parsing against sites that explicitly disallow it, with real risk of IP/rate-limit bans on the shared GitHub Actions runners. The legitimate path to more MENA coverage is what's already working — hand-seeding a company's real ATS board (Careem, Thndr, Bosta, Mercor, Incorta) or building the Workable/BambooHR/Recruitee fetchers above (Lane M3), since a company posting to Wuzzuf/Bayt usually has a real ATS underneath.
- **Niche developer-focused job boards — Honeypot.io, Otta.com, Cord.co** — evaluated 2026-09-07 alongside the general boards above.
  - **Honeypot.io** and **Otta.com** — both domains hang/timeout on every connection attempt (TLS connects, then nothing). Consistent with their actual fates: Honeypot was acquired and wound down around 2023; Otta was acquired by Welcome to the Jungle in 2024 and folded into that product. Neither has a live site to fetch from.
  - **Cord.co** (redirects to `cord.com`) — its JS bundle (`assets.co-hire.com/react/p/static/*.js`) shows the whole product is gated behind authenticated `/api/v2/account/candidate/...` endpoints (`onboarding/like`, `onboarding/skip`, `candidate/feed`) — a Tinder-style swipe feed for logged-in candidates, not a browsable public job board. No public "list open jobs" endpoint exists to poll.
- **RemoteOK and We Work Remotely** — evaluated 2026-09-07 as candidates to widen global/remote coverage. Both are real, live, free, keyless APIs (RemoteOK: `remoteok.com/api`, JSON; We Work Remotely: `weworkremotely.com/categories/remote-programming-jobs.rss`, RSS) — but rejected for the same rule that already excludes workopia and jobright-ai: **every apply link routes through the aggregator's own page, never the employer's.** Checked directly: RemoteOK's `url` and `apply_url` fields both point at `remoteok.com/remote-jobs/<slug>`; We Work Remotely's RSS `<link>` points at `weworkremotely.com/remote-jobs/<slug>`. Neither exposes the underlying employer application URL anywhere in its feed. RemoteOK's own API terms also ask for backlink attribution "or they'll suspend access" — a normal ask for their own site, but a sign the relationship is "traffic funnel back to RemoteOK," a different posture than Greenhouse/Lever/Ashby (whose employer customers want the raw postings polled with no strings attached). Neither site is disreputable — this is a data-shape rejection, not a trust one — but it means adding them would introduce the one thing this repo has twice already refused: a row that looks identical to every other row in the table but silently takes the user to a middleman page instead of the real application.
- **EURES** (European Job Mobility Portal, EU-wide, 31 countries) — evaluated 2026-09-07 alongside the German Arbeitsagentur integration above. Its job-search API (`europa.eu/eures/api/jv-searchengine/public/jv-search/search`) is real, live, and fully keyless (confirmed with a live POST returning 255K+ matching records) — but like Arbeitsagentur, it's an unofficial reverse-engineered API, not a published one ([rorar/EURES-API-Documentation](https://github.com/rorar/EURES-API-Documentation)). Unlike Arbeitsagentur, though, there's no clean canonical URL to build: the real originating link is buried as a raw HTML `<a href>` inside a free-text `applicationInstructions` field on the job-detail endpoint (`jv-searchengine/public/jv/id/{id}`), and its shape differs per contributing national employment service — a Swedish listing's link went to Sweden's own "Platsbanken" board, itself one more hop from the employer, with no shared schema across the other 30 countries to build a general parser against. Deferred rather than rejected outright: buildable in principle, but would need per-country research into each PES's `applicationInstructions` format before it could be reliable, a materially bigger lift than every other source's fixed JSON contract.
- **huzzle-app/Graduate-Jobs-with-Visa-Sponsorship-UK** — evaluated 2026-09-07. Last pushed 2024-04-24 — over two years stale at time of check. Same reasoning as vanshb03's removal: a job-listing repo that hasn't been touched in years is, in practice, all dead/expired links by now. Not pursued.
- **shubheksha/companies-sponsoring-visas** — evaluated 2026-09-07. Different in kind from the above (a hand-maintained table of *which companies* sponsor visas — Stripe, Shopify, Datadog, Klarna, … — not job postings), also last pushed 2024-03-28 and the file itself warns "please verify this information as it may not always be fully up-to-date." **Not usable the way it was proposed** (a static `config/visa_sponsors.yml` that blanket-tags every posting from a listed company as `visa_sponsorship: true`) — that's the exact fabrication this repo's B4 feature deliberately avoids: `visa_sponsorship` is set by `patterns.py`'s `detect_requirements()` **only when a specific posting's own description text says so**, precisely because a company's general policy doesn't mean every role/location/level it posts is actually sponsored. A stale, unverified, company-wide flag would be a real regression from that standard, not an enhancement. Not pursued.
- **visajobs.xyz** — evaluated 2026-09-07. A real site with real content — checked a live country page (`/jobs-in-germany/`) and every link goes straight to the employer's own careers page (e.g. `adjoe.io/company/careers/?j_id=...`), passing the direct-link rule. But it's a static-site-generated collection of individual HTML pages (per-country/per-role), not a markdown table or JSON API — would need a bespoke HTML scraper rather than reusing the existing generic parser, and its total volume ("320+ roles") is modest. Not built now; a candidate to revisit if someone wants to write that scraper.
- **forgeapply/internships-and-new-grad-jobs** — evaluated 2026-09-07. Actively updated (60,000+ postings claimed, daily refresh), but every single apply link routes through `forgeapply.com/j/<slug>?utm_source=github&utm_medium=referral&utm_campaign=early_career_repo` — their own site, never the employer's — same rule that already excludes workopia, jobright-ai, RemoteOK, and We Work Remotely.
- **Ploy's UK technology application trackers** (`get.ploy.club/opentracker/uk-technology-application-tracker-{internships,graduates}`) — evaluated 2026-09-07. Both are Framer-built marketing pages for the Ploy app; the actual job table isn't in the page at all — it's rendered from an embedded Notion database (`notion.site`). Notion has no public JSON API for this, so pulling it would mean reverse-engineering Notion's private internal API — same risk category as the EURES/Arbeitsagentur "unofficial API" tradeoff below, but with a much smaller payoff (one UK-only niche list) and a stricter ToS posture. Not pursued.
- **vanshb03/{Summer2027-Internships, New-Grad-2027}** — *was* a source; **removed 2026-09-06**. In practice it was the single biggest contributor of dead / "job not found" links: its rows skew heavily toward soft-404-prone hosts (joinbytedance.com, jobs.apple.com, metacareers.com, iCIMS), its Amazon links carried job ids ~3,000,000 (years stale — current ids are ~10,500,000), and every Microsoft row pointed at one generic `apply.careers.microsoft.com/careers?query=intern…` search URL rather than a real posting. Everything it covered is already pulled fresher from a live source (Amazon via its own API; Adobe/Roblox/Stripe/Duolingo/Pinterest via their Greenhouse/Ashby/Workday boards; Google/Meta/Apple/Microsoft via `config/aggregate_links.yml` + SimplifyJobs).

## Notes

- Config-file changes (`companies_allowlist.yml`, `extra_job_boards.yml`) don't need a new row here — this file tracks *where the data comes from*, not which companies are accepted.
- If a fetcher is added or removed in `scripts/fetch.py` or `scripts/public_sources.py`, update this file and the "How it works" section in [CONTRIBUTING.md](CONTRIBUTING.md) in the same change.
