# Data Sources

Every website, repo, and API the pipeline pulls from. Hand-maintained — not rebuilt by the pipeline; update it (see [CONTRIBUTING.md](CONTRIBUTING.md)) when a fetcher is added or removed. Pipeline *output*: [data/README.md](data/README.md). Career-prep resources for job seekers, not pipeline inputs: [data/resources.md](data/resources.md).

## Considered, not added

- **workopia/UK-Graduate-Jobs** + sibling country repos (France, Germany, Spain, Netherlands, etc.):
  - Large, actively-updated family of graduate-job trackers.
  - Skipped: apply links point at Workopia's own site (an intermediary/lead-gen page), not the employer's original posting — breaks the "every row links straight to the real application page" rule.
  - Table is HTML, not a plain pipe-table, so it wouldn't reuse the existing generic parser.

- **jobright-ai/2026-Software-Engineer-New-Grad**:
  - Actively maintained, but every apply link routes through `jobright.ai/jobs/info/<id>?utm_campaign=…` (its own tracking redirect), not the employer's page — same rule as workopia.
  - Caps its list to "the last 7 days" and pushes users to a paid Airtable link for the rest.

- **Non-standard ATSes surfaced by the MENA push** — the region's employers cluster on ATSes the pipeline didn't originally read. Each has a public keyless JSON API and follows the same pattern as the existing fetchers; `scripts/verify_extra_boards.py` has a checker for each (`platform:token`) — verify the endpoint shape (`--dump platform:token`) before building:
  - **PinpointHQ** — `{company}.pinpointhq.com/postings.json` (or a custom domain like `careers.moneyfellows.com`). **Built 2026-09-06** (`fetch_pinpoint_jobs`) — supported public-layer source, see the table above. First tenants: **Tabby** (`tabby.pinpointhq.com`, 44 postings incl. "Senior Fullstack Engineer"), **Money Fellows** (`careers.moneyfellows.com`, 8, Cairo).
  - **Workable** — `apply.workable.com/api/v1/widget/accounts/{slug}?details=true`. **Built 2026-09-07** (`fetch_workable_jobs`) — supported public-layer source, see the table above.   - `jobs.careers.microsoft.com` is an Eightfold-hosted SPA; the real data API is on `gcsservices.careers.microsoft.com`, which from this environment serves a TLS certificate that doesn't validate for that hostname (and `microsoft.eightfold.ai` 403s).

- **LinkedIn company job pages** (`linkedin.com/company/<x>/jobs`):
  - Enumerating a company's jobs from LinkedIn means scraping against its bot protection at volume — forbidden by the "respect source terms" rule (LinkedIn is used *only* via its unauthenticated guest job-posting endpoint, read-only, one id at a time, for the closed-link check in `scripts/net.py`).
  - Also unnecessary: a company's LinkedIn listings are cross-posts of its own ATS board — fetching the Greenhouse/Lever/Ashby/Workday board (or an `aggregate_links.yml` row for a bespoke careers site) gets the same roles from a keyless, allowed source. Tell for which ATS: the "Powered by …" line in the company careers page footer.

- **General consumer job boards — Wuzzuf, Bayt, LinkedIn Jobs, Indeed, Glassdoor, StepStone, GulfTalent, Naukrigulf** — evaluated 2026-09-07 after a request to widen MENA/EMEA coverage. Confirmed per-site, not assumed:
  - **Wuzzuf** — `robots.txt` explicitly disallows the exact URL shapes needed (`Disallow: /*filters`, `/*?a=`, `/*?o=`, `/*?l=`, `/*?t=` — filtered search pages and individual job-posting links both) and names `ClaudeBot` in its disallow list. No JSON API backs the search pages — server-rendered HTML, no `__NEXT_DATA__`/API reference to key off.
  - **Bayt** — `robots.txt` disallows `*filters[` and all of `/en/jobs/*-jobs/` (search-results path) for every crawler, plus a blanket `Disallow: /` naming `LinkedInBot`/`IndeedBot`. Its "REST JSON Jobs" feed is a paid partner integration, not keyless.
  - **LinkedIn** — even a bare `robots.txt` request returned a Google reCAPTCHA challenge page. No path without solving CAPTCHAs at scale.
  - **Indeed** — the public "Job Search API" was discontinued; what remains needs Publisher/Partner Program approval, not a keyless call.
  - **Glassdoor** — no public API; even `robots.txt` is served from behind Cloudflare with a redirect, consistent with heavy bot-protection on the job pages.
  - **StepStone** — its job-feed API is a paid XML jobfeed arrangement, not free/keyless.
  - **GulfTalent, Naukrigulf** — same category (commercial portals monetizing search traffic); no public JSON API, same bot-blocking/partner-gating pattern.
  - All are consumer job-search engines monetizing aggregated listings — structurally unlike Greenhouse/Lever/Ashby/Workday, whose employer customers *want* postings polled. Scraping them risks IP/rate-limit bans on shared GitHub Actions runners. The working path to more MENA/EMEA/Europe coverage: hand-seed a company's real ATS board (MENA: Careem, Thndr, Bosta, Mercor, Incorta, Foodics, Lucidya, Salla; Europe 2026-09-09: Monzo, GoCardless, Celonis, SumUp, Wayve, Doctolib, Qonto, BlaBlaCar, ElevenLabs, Pennylane, Alan, Legora + more — see `scripts/verify_extra_boards.py --europe`), since a company posting to Wuzzuf/Bayt usually has a real ATS underneath.

- **Niche developer-focused job boards — Honeypot.io, Otta.com, Cord.co** — evaluated 2026-09-07:
  - **Honeypot.io** and **Otta.com** — both domains hang/timeout on every connection attempt (TLS connects, then nothing). Matches their fates: Honeypot acquired and wound down ~2023; Otta acquired by Welcome to the Jungle in 2024 and folded into that product. Neither has a live site to fetch from.
  - **Cord.co** (redirects to `cord.com`) — its JS bundle (`assets.co-hire.com/react/p/static/*.js`) shows the whole product gated behind authenticated `/api/v2/account/candidate/...` endpoints (`onboarding/like`, `onboarding/skip`, `candidate/feed`) — a Tinder-style swipe feed for logged-in candidates, not a browsable public board. No public "list open jobs" endpoint to poll.

- **RemoteOK and We Work Remotely** — evaluated 2026-09-07 to widen global/remote coverage:
  - Both real, live, free, keyless APIs (RemoteOK: `remoteok.com/api`, JSON; We Work Remotely: `weworkremotely.com/categories/remote-programming-jobs.rss`, RSS) — but rejected for the same rule as workopia/jobright-ai: **every apply link routes through the aggregator's own page, never the employer's**.
  - Confirmed directly: RemoteOK's `url`/`apply_url` both point at `remoteok.com/remote-jobs/<slug>`; We Work Remotely's RSS `<link>` points at `weworkremotely.com/remote-jobs/<slug>`. Neither exposes the employer application URL anywhere in its feed.
  - RemoteOK's API terms also ask for backlink attribution "or they'll suspend access" — a sign the relationship is "traffic funnel back to RemoteOK," unlike Greenhouse/Lever/Ashby (employer customers want raw postings polled, no strings).
  - Not a trust issue, a data-shape one — but adding them would mean a row indistinguishable from every other row silently taking the user to a middleman page instead of the real application.

- **EURES** (European Job Mobility Portal, EU-wide, 31 countries) — evaluated 2026-09-07 alongside Arbeitsagentur:
  - Its job-search API (`europa.eu/eures/api/jv-searchengine/public/jv-search/search`) is real, live, fully keyless (confirmed with a live POST returning 255K+ matching records) — but, like Arbeitsagentur, unofficial/reverse-engineered, not published ([rorar/EURES-API-Documentation](https://github.com/rorar/EURES-API-Documentation)).
  - Unlike Arbeitsagentur, no clean canonical URL: the real originating link is a raw HTML `<a href>` inside a free-text `applicationInstructions` field on the job-detail endpoint, shape differing per contributing national employment service (a Swedish listing led to Sweden's own "Platsbanken" board, one more hop from the employer) — no shared schema across the 30 countries to parse against.
  - **Deferred, not rejected** — buildable in principle, but needs per-country research into each PES's `applicationInstructions` format, a materially bigger lift than every other source's fixed JSON contract.

- **huzzle-app/Graduate-Jobs-with-Visa-Sponsorship-UK** — evaluated 2026-09-07. Last pushed 2024-04-24, over two years stale. Same reasoning as the vanshb03 removal — a years-untouched job-listing repo is, in practice, all dead/expired links. Not pursued.

- **shubheksha/companies-sponsoring-visas** — evaluated 2026-09-07:
  - A hand-maintained table of *which companies* sponsor visas (Stripe, Shopify, Datadog, Klarna, …), not job postings — different in kind from the above. Also last pushed 2024-03-28, and the file itself warns "please verify this information as it may not always be fully up-to-date."
  - **Not usable as proposed** — a static `config/visa_sponsors.yml` blanket-tagging every posting from a listed company as `visa_sponsorship: true` is the exact fabrication B4 deliberately avoids: `patterns.py`'s `detect_requirements()` sets `visa_sponsorship` **only when a specific posting's own description text says so**, since a company's general policy doesn't mean every role/location/level it posts is actually sponsored. A stale, unverified, company-wide flag would be a regression from that standard. Not pursued.

- **visajobs.xyz** — evaluated 2026-09-07:
  - A real site with real content — a live country page (`/jobs-in-germany/`) checked, every link goes straight to the employer's own careers page (e.g. `adjoe.io/company/careers/?j_id=...`), passing the direct-link rule.
  - But it's a static-site-generated collection of individual HTML pages (per-country/per-role), not a markdown table or JSON API — needs a bespoke HTML scraper, and total volume ("320+ roles") is modest. Not built now; a candidate to revisit.

- **forgeapply/internships-and-new-grad-jobs** — evaluated 2026-09-07. Actively updated (60,000+ postings claimed, daily refresh), but every apply link routes through `forgeapply.com/j/<slug>?utm_source=github&utm_medium=referral&utm_campaign=early_career_repo` — their own site, never the employer's. Same rule that excludes workopia, jobright-ai, RemoteOK, We Work Remotely.

- **Ploy's UK technology application trackers** (`get.ploy.club/opentracker/uk-technology-application-tracker-{internships,graduates}`) — evaluated 2026-09-07:
  - Both are Framer-built marketing pages for the Ploy app; the actual job table is rendered from an embedded Notion database (`notion.site`), not present in the page.
  - Notion has no public JSON API for this — pulling it means reverse-engineering Notion's private internal API, same risk category as the EURES/Arbeitsagentur "unofficial API" tradeoff, but with a much smaller payoff (one UK-only niche list) and stricter ToS posture. Not pursued.

- **Third-party hackathon aggregators — Hackalist, 0xarchit/hackathon-api, dev-shetty/hackathon-finder, lorenzopalaia/HackTrack-EU, TeeWrath/NoteXplorer-API** — evaluated 2026-09-07 to widen event coverage beyond Devpost/Unstop/Devfolio. None added:
  - **Hackalist** (`hackalist.github.io`) — the claimed `/api/1.0/{year}/{month}.json` endpoint 404s for every month now; the site redirects to `www.hackalist.org` with no working API; its own `<meta>` describes it as *"An archive of hackathons from around the world (2014-2025)"*. GitHub repo's `api/1.0/` folder stops at `2025`, last pushed 2026-04-09. Dead for live data.
  - **0xarchit/hackathon-api**, **dev-shetty/hackathon-finder**, **TeeWrath/NoteXplorer-API** — each a personal hosted scraper re-aggregating Devpost/Unstop/Devfolio/MLH. Two problems: (1) mostly re-serve platforms this pipeline already polls **directly**, adding a middleman hop; (2) the hourly job would then depend on a hobby project's free Vercel/Render deployment staying up — fragility this repo accepts for no other source. 0xarchit last pushed 2025-12-23.
  - **lorenzopalaia/HackTrack-EU** — genuinely active (pushed 2026-09-06), EU-focused, but same two objections: personal `hacktrack-eu.vercel.app` hosting, and a scraper layer over the same platforms rather than a primary source.
  - The real gap these point at is **MLH (Major League Hacking)** season/member events, under-covered by Devpost/Devfolio/Unstop — but MLH has no public JSON API (`/seasons/{year}/events` 302-redirects bots, no `ld+json`, no maintained community JSON mirror), the same "HTML scrape against bot protection" refused elsewhere. `config/events.yml` remains the hand-curated escape hatch for a specific must-have event.

- **Second batch, evaluated 2026-09-07** (awesome-lists + GitHub topic API + HackerEarth):
  - **mbiesiad/awesome-hackathons**, **dribdat/awesome-hackathon** — markdown "awesome lists" of recurring hackathon *brands* (NASA Space Apps, Hash Code, Call for Code, Hacktoberfest…), no per-event dates, last pushed 2024-05, some entries already dead (Google Code Jam discontinued 2023). Not a data feed — one dated `config/events.yml` line is the right call for a specific recurring event.
  - **GitHub topic API** (`topic:hackathon` / `hackathon-template`) — real keyless REST API, but repos with those topics are *project submissions*, not event listings with dates/links. Pure noise here.
  - **jdorfman/awesome-json-datasets**, **sharmadhiraj/free-json-datasets** — generic public-API directories, nothing to do with events.
  - **HackerEarth** — **added** (`fetch_hackerearth_hackathons`, 2026-09-07). Its `/chrome-extension/events/` endpoint is keyless JSON, `url` points at the real event page, not `robots.txt`-disallowed — same category as the Devpost/Unstop/Devfolio internal APIs. Small (~6 featured events) but high-signal, MENA/India-heavy. See the table above.

- **vanshb03/{Summer2027-Internships, New-Grad-2027}** — *was* a source, **removed 2026-09-06**:
  - The single biggest contributor of dead/"job not found" links: rows skewed heavily toward soft-404-prone hosts (joinbytedance.com, jobs.apple.com, metacareers.com, iCIMS); Amazon links carried job ids ~3,000,000 (years stale — current ids are ~10,500,000); every Microsoft row pointed at one generic `apply.careers.microsoft.com/careers?query=intern…` search URL, not a real posting.
  - Everything it covered is already pulled fresher from a live source: Amazon via its own API; Adobe/Roblox/Stripe/Duolingo/Pinterest via their Greenhouse/Ashby/Workday boards; Google/Meta/Apple/Microsoft via `config/aggregate_links.yml` + SimplifyJobs.
